# Data Model

Referral Bridge has **no SQL database and no migration files**. It stores records as JSON documents in collections, in one of two places:

| Where | When | Limits |
|------|------|--------|
| Claude artifact database (`window.claude.use("db")`) | When the app is opened inside Claude. Syncs across your devices. | Each collection loads up to 1,000 records (signals: 3,000). |
| Browser `localStorage`, key `rb-data` | When the app is opened as a plain web page. This device only. | About 5 MB total. |

The app also keeps two small `localStorage` keys, `rb-last` and `rb-prev`, to remember your last visit for the "new since last time" counts on Today.

Every record has an `id` (string), plus `createdAt` and `updatedAt` (ISO timestamps) that the app sets on save.

This document is the schema. A future SQL schema and its migrations should be written from it.

### `outreach` — your calls, emails and visits (in code: `S.outreach`)

`bizId`, `channel` (call, email, text, linkedin, visit, other), `outcome` (none, noanswer, voicemail, spoke, interested, booked, notint, bad), `contact`, `note`, `at` (ISO), `apptAt` (`YYYY-MM-DD`), `apptTime` (`HH:MM`).

### `news` (in code: `S.news`)

`title`, `url`, `sourceName`, `publishedAt`, `addedAt`, `expiresAt`, `summary`, `impact`, `industries` (string[], may include `all` or `Healthcare (all)`), `states` (string[]), `needs` (`{needId: delta}`, e.g. `{"banking": 0.05}`), `outlook` (`{industry: +n | -n}`).

### `leadRequests` — "find me businesses" requests (in code: `S.req`)

`kind` (biz or coi), `state`, `county`, `industry`, `profession`, `count`, `notes`, `status` (Waiting, Done), `research` (boolean), `found` (number).

### `contactRequests` — priority research requests (in code: `S.creq`)

`bizId`, `name`, `status` (Waiting, Done), `result`, `doneAt`.

### `providerUsage` (in code: `S.usage`)

One record per data source; `id` is the provider id. `calls`, `cacheHits`, `estCost`, `day`, `dayCalls`, `lastRun` (`{bizId: ISO}`), `lastRunAt`.

### `settings`

A single record with `id: "providers"`:

`enabled` (`{providerId: boolean}`), `quotaDefault` (number, default 200), `revMin`, `revMax` (numbers or null), `revUnknown` (boolean), `newsOff` (boolean), `climateFocus` (growth, both, off), `learnOff` (boolean), `autoResearch` (boolean).

### `botlog` — run reports from scheduled research

`bot` (news, prospector, research), `ranAt` (ISO), `summary`, `links` (`[{title, url}]`).

## Reference data (in code, not stored)

These are constants in `src/index.html`. Adding a value there is all it takes.

- `SIGNAL_TYPES`: 49 signal types, each with label, category, weight, half-life in days, and the needs it implies
- `NEED_DEFS`: 20 needs and which professions serve each
- `NEEDS`: typical professions needed per industry
- `PROVIDER_CATALOG`: ~100 data sources in 14 categories
- `MOCK`: 16 test connectors that generate labeled test signals

## Migrations

There are no migration files. Two compatibility rules run in code every time data loads:

1. **Match status:** `Closed Won` (Salesforce wording) is renamed to `Closed`.
2. **Legacy trigger:** a business's old single `trigger` field (or a formation date within the last year) is read as a signal. It is computed on the fly and never written back.
